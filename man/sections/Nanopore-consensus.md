# Nanopore consensus

This module builds consensus sequences from Nanopore amplicon FASTQ files. It is intended as a lighter, easier-to-maintain alternative to MSI when the next step is taxonomic assignment with the existing SLIM modules.

The module does not perform taxonomy. It produces FASTA consensus sequences that can be passed to the FASTA taxonomic-assignment modules.

## Workflow

For each input FASTQ file, SLIM runs:

1. **cutadapt primer trimming**, when a primer FASTA is provided and primer trimming is enabled.
2. **VSEARCH filtering** to keep reads within the requested length range, and optionally filter by expected errors.
3. **VSEARCH dereplication** to collapse identical reads and keep abundance information.
4. **VSEARCH clustering** to produce draft amplicon consensuses.
5. **minimap2** to map filtered reads back to the retained draft consensuses. The mapping file is kept in the results archive.
6. **Medaka**, optionally, to polish the retained draft consensuses with the original filtered reads.
7. **minimap2** to map each sample's filtered reads back to the final polished FASTA and count reads per consensus.

All per-sample consensus FASTA files are concatenated into one final consensus FASTA.

## Inputs

**Input Nanopore FASTQ pattern**

A FASTQ file or wildcard pattern. Examples:

```text
sample.fastq
*.fastq
barcode*_reads.fastq.gz
```

Wildcard groups made with the wildcard-creator module can also be used.

**Primer FASTA file**

Optional FASTA file containing the forward primer as the first sequence and the reverse primer as the second sequence. When primer trimming is enabled, SLIM removes the forward primer and the reverse-complemented reverse primer before VSEARCH and Medaka. cutadapt is run with reverse-complement handling when the installed cutadapt version supports it, so reads in the opposite orientation can be handled automatically.

By default, reads without a detected linked primer match are kept. This is deliberate for Nanopore data, where primer ends can be noisy. Enable the stricter discard option only when primer matching is reliable and you want to remove all reads that do not contain both expected primer ends.

## Outputs

**Consensus FASTA**

The final consensus sequences. If Medaka polishing is enabled, these are Medaka-polished sequences. If Medaka polishing is disabled, these are the retained VSEARCH draft consensuses. Sequence IDs are prefixed with the sample name.

**Run statistics**

A TSV table with one row per input file:

```text
sample
raw_reads
filtered_reads
dereplicated_sequences
draft_clusters
retained_clusters
consensus_sequences
polishing
```

**OTU table**

A TSV table with consensus IDs as rows and samples as columns. Counts are generated by mapping each sample's filtered reads to the final consensus FASTA with minimap2, keeping the best consensus hit for each read, and counting reads per consensus.

**Full results archive**

A `.tar.gz` archive containing primer-trimming logs and trimmed reads, filtered reads, dereplicated FASTA files, draft consensuses, retained draft consensuses, minimap2 PAF mappings, Medaka output folders when polishing is enabled, per-sample FASTA files, OTU-count intermediates, the final FASTA, the OTU table, and the stats table.

## Parameters

**Read length filter**

Default: minimum `100`, maximum `5000`.

Reads shorter or longer than these thresholds are discarded before clustering. Set these values to match the expected amplicon size and the amount of length variation you expect.

**VSEARCH maximum expected errors**

Default: `0`, which disables this filter.

When set above zero, VSEARCH removes reads whose expected error count is higher than this value. This can be useful for stricter consensus generation, but Nanopore quality scores can vary strongly by basecaller and run type, so the default is intentionally permissive.

**Trim primers from reads before consensus**

Default: enabled.

When enabled and a primer FASTA is supplied, primer sequences are removed before consensus generation, so the final consensus FASTA and OTU table are based on insert sequences without primer tails. Disable this option to keep primer sequences in the reads used for clustering and polishing.

**Primer max error rate**

Default: `0.20`.

This is passed to cutadapt as its maximum allowed error rate for primer matching. A permissive value is useful for Nanopore reads because primer regions can contain basecalling errors. Lower it for high-quality reads with reliable primer sequence, or increase it if true reads are being missed during primer trimming.

**Discard reads without linked primer match**

Default: disabled.

When disabled, cutadapt trims primer matches it can find but keeps reads even if the linked forward/reverse primer pattern is not detected. This prevents accidental loss of most reads when primer ends are noisy. When enabled, reads without the linked primer match are discarded.

**VSEARCH clustering identity**

Default: `0.90`.

This controls how similar dereplicated reads must be to form one draft consensus. Increase it to split closely related amplicons. Decrease it if reads are noisy or if you expect more within-target variation.

**Minimum reads per draft consensus**

Default: `5`.

Draft clusters supported by fewer reads are discarded before polishing. Increasing this value reduces low-abundance noise. Decreasing it can recover rare targets, but may also produce less reliable consensuses.

**Medaka model**

Default: `auto`.

With `auto`, SLIM does not pass `-m` to `medaka_consensus`, so Medaka uses its own default behaviour. For best polishing, replace `auto` with the model matching your basecaller, chemistry, and speed mode. You can list installed models inside the container with:

```bash
medaka tools list_models
```

**Polish draft consensuses with Medaka**

Default: enabled.

When enabled, Medaka polishes retained VSEARCH draft consensuses. When disabled, the module skips Medaka and uses the retained VSEARCH draft consensuses directly. Disable this on machines where Medaka or its TensorFlow dependency crashes with an illegal CPU instruction, or when you want a faster first pass.

**Use VSEARCH draft consensuses if Medaka fails**

Default: enabled.

When enabled, the module does not abort the whole run if Medaka fails for one sample. Instead, it records the Medaka failure in the log and uses the retained VSEARCH draft consensuses for that sample. The stats table records this in the `polishing` column. Disable this option if you want Medaka failures to stop the pipeline.

## Notes

Medaka polishing is usually the slowest step. Runtime scales with read count, number of retained draft consensuses, and available CPU cores.

If Medaka fails with exit code `132`, this usually indicates an illegal CPU instruction from the installed binary stack. That is a CPU compatibility issue, not a RAM shortage. Disable Medaka polishing or rebuild/install Medaka for the target machine.

SLIM installs Medaka with the CPU PyTorch wheels by default because most SLIM deployments do not have NVIDIA CUDA available inside the container. The Docker build uses `SLIM_MEDAKA_BACKEND=auto`: if `nvidia-smi` or `/usr/local/cuda` is visible during the image build, it installs the CUDA-capable stack; otherwise it installs CPU-only Medaka. To force a CUDA-capable Medaka stack for a suitable NVIDIA GPU host, build with:

```bash
docker build --build-arg SLIM_MEDAKA_BACKEND=gpu -t slim .
```

or the equivalent `podman build` command. To force CPU-only Medaka, use `--build-arg SLIM_MEDAKA_BACKEND=cpu`. The module log reports whether PyTorch sees CUDA at runtime.

If the module fails because no clusters survive, lower the minimum reads per draft consensus or the clustering identity. If it produces too many similar consensuses, increase the clustering identity and/or the minimum reads threshold.
