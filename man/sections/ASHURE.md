# ASHURE

The `ashure` module runs the ASHURE pipeline for long-read amplicon data generated by rolling-circle amplification. These reads can contain repeated copies of the same original DNA fragment, known as concatamers. ASHURE uses those copies to build consensus sequences and cluster them.

## Workflow

The module runs the following ASHURE steps:

1. Pseudo-reference generation (`prfg`).
2. Concatamer identification (`fgs`).
3. Consensus error correction (`msa`).
4. Primer identification (`fpmr`).
5. OPTICS clustering (`clst`).

`fgs` and `msa` are intended for reads containing more than one concatamer.

## Inputs

### Input FASTQ Files

FASTQ files to process. To select multiple FASTQ files at once, use a wildcard pattern created by the [wildcard creator](/man/sections/wildcard_creator.md).

### Primers File

FASTA file containing the forward primer as the first sequence and the reverse primer as the second sequence. Only IUPAC nucleotide characters are allowed.

```fasta
>forward_primer
GAACCTGGTTGATCCTGCCAGT
>reverse_primer
GGTGATCCTTCTGCAGGTTCACCTAC
```

## Parameters

* Read length limits (`prfg`): minimum and maximum allowed read length.
* Minimum cluster size (`clst`): minimum number of sequences used for multiple alignment around a centroid.
* Cluster merge threshold (`clst`): threshold used to merge clusters.
* Sweep partitions (`clst`): number of partitions used when selecting poorly aligned sequence subsets during clustering.
* Sequence subsample size (`clst`): number of sequences sampled during clustering sweeps.
* Clustering iterations (`clst`): number of clustering iterations to run.

## Outputs

* Consensus sequences.
* Primer-trimmed consensus sequences.
* Cluster-center sequences.
